# Phase 0.3 — чтение и контекст студии

Дата: 12.09.2026. Изменения локальные в ветке `codex/phase-0-migration-baseline`.

## Исправлено

- `src/server/auth/context.ts`: единая проверка настоящей сессии, активного членства, активной студии и нужного разрешения. Переданный studioId проверяется относительно пользователя сессии. Выбор студии по умолчанию идёт только из активных членств с устойчивой сортировкой.
- `getCurrentStudioId`: убран fallback первой студии. Переданный userId должен совпадать с пользователем текущей сессии; чужой userId или отсутствие членства возвращают undefined.
- Запросы clients/services/masters, поиск и прямой запрос студии защищены на сервере. В глобальном поиске каждый тип результата проверяет своё read-разрешение. Исправлен поиск enum-категории услуги через приведение к text.
- Списки страниц проверяют read-разрешение; страницы деталей используют защищённые queries. Для service details/master schedule исправлено ожидание асинхронных params.
- Медицинский профиль загружается только после подтверждения принадлежности клиента студии и MEDICAL_PROFILE_READ. Нельзя прочитать его по чужому clientId. Без права вкладка и данные не передаются в клиентский компонент. Медицинские события также исключены из истории при отсутствии этого права.
- Чтение медиа проверяет клиента и разделяет фотографии/согласия на сервере. CONSENT_READ нельзя обойти через общий запрос медиа. Существующая проблема хранения согласий как обычных media остаётся в плане документов.
- `hasPermission`: персональные overrides выбираются именно для запрашиваемого permissionId. Если в старой схеме есть противоречащие дубли, deny имеет приоритет. SUPER_ADMIN semantics и матрица ролей пока не переработаны.
