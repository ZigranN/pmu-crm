# Phase 2.1 — каталог услуг

Реализовано в ветке `codex/phase-2-service-catalog`, поверх Phase 1.4. Merge и миграция Neon не выполняются этой задачей.

## Контракт

Миграция `0009_service_catalog.sql` добавляет справочники category/zone/technique и 13 определений услуг §8. Каталог студии ссылается на определения через FK; PMU имеет two sessions, Remover — variable. Category/zone/technique нельзя вводить свободным текстом. Refresh/Remover используют `cycle_zone`: конкретная зона будет определяться treatment cycle.

Цена хранится целыми центами: fixed, estimate, range, master_quote. Quote имеет NULL, а не фиктивный ноль. Диапазоны/ориентиры явно отмечены в UI и не являются согласованной ценой клиента. Базовые суммы соответствуют §8. Индивидуальные цены и Custom Offer — следующий шаг 2.2.

Начальный PMU — 120 минут, Refresh/Remover — 60; дополнительные буферы нормализованного каталога равны нулю. Для двух laminations и двух Skin услуг ТЗ не задаёт длительность: они создаются неактивными с NULL, владелец должен настроить время. Новая функция `getBookableServices` исключает legacy/unconfigured; будущий Calendar Engine обязан её использовать. Старый список услуг мастера пока сохраняет совместимость с legacy.

Подготовка/постуход ссылаются только на активные шаблоны соответствующего назначения в своей студии. Тексты не выдумываются. Утверждение/версионирование знаний и отправка материалов относятся к последующим фазам.

## Импорт и история

Owner может импортировать каталог из UI. Повторный импорт сохраняет изменённые и архивные записи, уникальность `(studioId, catalogCode)` защищает от дублей. Создание использует command receipt; изменения и импорт выполняются под studio lock с атомарным audit.

Старые услуги остаются `catalogVersion=0` с прежними ID, ценой, временем и буферами. Можно явно сопоставить запись со справочником или выбрать дубли у основной услуги. Дубли архивируются с `supersededById`; старые appointments, snapshots и master-service links сохраняются. Допуск мастеров копируется к основной записи. Это не автоматическое угадывание эквивалентности услуг.

## Запуск

После отдельно согласованного применения миграций можно импортировать каталог кнопкой Owner. Альтернатива: `SEED_PHASE3_CATALOG=true npm run db:seed` с локально настроенным окружением и уже зарегистрированным Owner. Флаг по умолчанию выключен. Seed запускается Node с условием react-server; зависимость server-only указана явно. Не запускать seed против Neon в рамках текущей задачи.

## Проверки

96 unit/integration tests и 4 migration tests: 13 исходных услуг, повторный seed/import, конкурентное создание, FK/tenant isolation, цены и длительности, сохранение legacy appointment snapshots, разбор дублей и audit rollback. Добавлен браузерный сценарий Owner на мобильной ширине: импорт, заполнение длительности, сохранение цены при повторном импорте и диапазон цены.

CI проверяет отдельный импорт seed runtime без подключения к БД, typecheck/lint/tests/build и браузерные сценарии на disposable PostgreSQL 17. Результат конкретного CI запуска следует проверять в PR; наличие теста само по себе не означает его прохождение.
