# Phase 0.4 — целостность изменений

Основание: main после merge PR #1 (`6f9814d`). Работа ведётся отдельной веткой `codex/phase-0-mutation-integrity`.

## Изменения

- Мастер и привязки услуг сохраняются одной транзакцией вместе с audit. Проверяются принадлежность услуги студии, доступность новых услуг и дубли IDs. Чужой/отсутствующий мастер не даёт изменять связи или возвращать фиктивный успех. Пропущенное serviceIds сохраняет связи; явный [] очищает их. Ранее привязанные архивные услуги разрешено сохранить.
- Запрос мастера возвращает услуги для формы. Nullable поля нормализованы для формы: редактирование существующего мастера не требует заполнять необязательные поля.
- Два медицинских entrypoint используют одну команду: проверка active client + studio, row lock, upsert, activity и audit в общей транзакции. Ошибка обязательной истории откатывает изменение. Медицинский текст не дублируется в audit metadata.
- Медиа и согласия проверяют actor/permission, клиента, appointment и procedure session до provider I/O. После загрузки ссылки проверяются повторно под блокировкой. Media, consent, audit и activity сохраняются одной транзакцией; при ошибке новый внешний upload компенсируется удалением только незавершённого файла.
- CONSENT_UPLOAD проверяется и при обращении через общий media action. Подмена clientId в удалении согласия отвергается.
- Архивирование сохраняет consent record и исходный внешний файл. Скрытие из активных списков идёт через deletedAt связанного media; это ещё не система версионирования/подписи документов Phase 4.

## Миграция

Добавлена additive migration `0003_consent_archive_event.sql` и snapshot: новое значение `consent_archived` в activity_event_type. Ранее применённые SQL не изменялись. Миграция применяется только к тестовым БД в рамках этого шага.

**До выпуска кода в рабочее окружение требуется штатно применить 0003.** CI проверяет миграции на disposable PostgreSQL; это не применяет миграцию к Neon. Внешняя БД не менялась.

## Проверки

Локально: typecheck/lint/build:test, 4 migration tests, 36 Vitest tests (14 новых mutation tests), 3 HTTP smoke checks. Новые тесты проверяют чужие IDs, сохранение услуг, rollback при настоящей ошибке audit в PostgreSQL, обе медицинские формы, компенсацию незавершённого upload, проверку appointment другого клиента и архивирование без уничтожения файла.

Добавлен отдельный Playwright master-edit test: реальная регистрация/сессия на disposable PostgreSQL, редактирование имени мастера с null-полями, сохранение и повторная проверка привязок. GitHub CI должен подтвердить этот сценарий в Chromium. Для локального полного E2E нужен TEST_DATABASE_URL; в CI отсутствие этой переменной является ошибкой, а не причиной skip.

## Оставшиеся ограничения

- Durable outbox/retries/cleanup queue и полная idempotency — Phase 1.4. Если компенсация внешнего upload сама завершится ошибкой, возможен незавершённый файл; фиксируется сообщение для диагностики. Это не обещание атомарности PostgreSQL и Cloudinary.
- Full role matrix, Master assignment scope и общая переработка audit — Phase 1. Изменённые команды уже используют обязательный transactional audit; остальные команды будут переведены отдельно.
- Версии, подписи, PDF и правила хранения согласий — Phase 4. Отдельного restore UI для архивных согласий пока нет.
- Следующий шаг — 0.5: seed, общий интерфейс и оставшиеся локальные дефекты.
